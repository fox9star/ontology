온톨로지 스튜디오 안정화 기록

2026-10-04 현재 폴더의 구현 변경과 확인 범위를 정리합니다. 실행 방법은 README, 상세 사용법은 manual.md에 있습니다.

온톨로지 품질 개선은 아래 기존 안정화 기준에 추가된 후속 변경입니다. 과거 테스트 수치와 API 확인 내역은 이번 스키마 변경의 검증 결과로 계산하지 않습니다.

HTTP 202, 요청 파일 생성, worker 시작은 각각 접수·준비 상태입니다. 완료 여부는 job.json의 상태, 실제 생성된 결과와 result.persisted의 저장 증거로 확인합니다. 생성된 텍스트를 보관했지만 검증·RDF 저장에 실패하면 validation_failed로 기록하고 원래 그래프를 유지합니다.

Codex가 선택한 실제 모델을 확인하지 못한 경우 모델 출처는 미확인으로 남깁니다. 앱은 모델 API 키를 요구하지 않으며 host worker가 저장된 ChatGPT 로그인을 사용합니다. Docker 웹 컨테이너에는 호스트의 로그인 세션을 복사하지 않습니다.

실제 Codex CLI 작업 codex_d462c6f4c4244f449fe64129838e1b2a가 completed로 기록됐고 실행 방식은 codex_cli_chatgpt입니다. 결과 파일의 SHA-256을 다시 계산해 94db8a7c8663bc7eef6c072f56f8eb5160aac89d71063f5cd5869e6e18ffbb0c와 일치함을 확인했습니다. 이 확인 작업은 save_to_graph: false로 실행해 RDF 저장을 요청하지 않았습니다.

복구와 데이터 보존

새 스냅샷은 스키마를 포함하지 않은 데이터 그래프만 저장합니다. 웹 복원은 선택한 도메인·프로젝트와 일치하는 새 스냅샷에 한정합니다. 이전 버전의 범위 정보가 없는 스냅샷은 과거 기록으로 보관하고 웹 비교·복원은 거부합니다. 파일 변조나 쓰기 실패에서도 원본 데이터가 유지되는지 검사합니다.

개체 삭제는 incoming/outgoing 관계를 제거한 후보 그래프를 검증합니다. 필수 참조가 깨지거나 등록 미디어의 RDF/manifest 정보가 달라지면 저장하지 않습니다. Codex 결과·개체 편집·복원은 동일한 공통 파일 잠금과 원자적 저장 경로를 사용합니다.

Docker의 checkout 디렉터리 공유는 원자적 파일 교체를 host worker와 웹에 함께 반영합니다. 미디어 파일은 ONTOLOGY_REGISTERED_ROOT_URI로 원래 등록 작업 폴더를 명시해 컨테이너 위치에 대응시킵니다. 최초 RDF/manifest의 파일 출처는 다시 쓰지 않고 엄격한 URI·SHA-256 검증을 유지합니다.

검증 범위

검사는 임시 폴더·임시 데이터 파일을 사용해 실제 예제와 등록 프로젝트 RDF를 수정하지 않습니다. 다음 동작과 실패 사례를 확인 대상으로 포함합니다.

  • 지속 작업 접수·조회, CLI 가용성, 실행권 충돌, 실제 결과 기록, 검증 실패 상태.
  • Codex 결과 출처·hash, 데이터 파일의 범위 분리와 원자적 저장.
  • 같은 초의 여러 스냅샷 ID, hash 변조, 경로 탈출, 다른 도메인·프로젝트 복원 거부.
  • 파일에 실제 복원된 그래프 재조회, 쓰기 실패 시 파일·메모리 상태 보존.
  • 구조가 같은 blank node의 의미적 Diff, 전체 수치와 URI 예시.
  • 생성 SHACL 실패, 필수 참조를 깨뜨리는 삭제 거부, 동시 생성 데이터 유실 방지.
  • 스레드·프로세스 간 파일 잠금, 동일 스레드 재진입, 직렬화·교체 실패 보존.
  • 로컬 클라이언트·Host·Origin 제한, 원격·cross-site 요청 거부, Docker 명시 모드.
  • 실제 미디어 존재·SHA-256·메타데이터 검사와 파일 누락·변조 실패.
  • 이전 6-domain 구현 기록에서는 대학 모델 검증을 지원하지 않았다. 현재 구현은 대학 shapes를 추가해 7개 프로파일 모두 SHACL을 지원한다.
  • 실행기 소유 확인, health check, 잘못된 PID와 점유 포트에서 임의 프로세스 보존.

전체 검사는 다음 명령으로 재현합니다.

.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check

최종 전체 검사는 194개, 31.552초였으며 실패 0·오류 0·건너뜀 0으로 통과했습니다. 패키지 버전은 requirements.lock.txt에 고정하고 설치 시 requirements.txt와 constraints를 함께 적용합니다.

최종 HTTP 확인에서 health, OpenAPI, 대학 모델 explorer, Codex 상태·목록, 로컬 identity, 프로젝트 스냅샷 목록, 출처 보고서의 8개 조회 경로가 200을 반환했습니다. foreign Origin을 보낸 POST는 403으로 거부됐습니다. 확인 시 웹 서버는 127.0.0.1:5000에 실행 중이었으며 실제 TCP listener도 확인했습니다.

포트 5055의 실행기 검사에서는 시작·동일 PID 재사용·종료 후 listener와 소유권 기록 제거를 확인했습니다. 렌더링된 화면 JavaScript는 node --check를 통과했습니다. Docker 실행 파일이 없어 컨테이너 실행은 확인하지 못했고, 브라우저 자동화 도구의 요청 헤더 정책 오류가 두 번 반복돼 화면 조작 검증은 완료하지 못했습니다. HTTP API·JavaScript 문법·임시 파일 기반 저장 검사는 위 결과에 포함됩니다.

Git 저장소를 main 브랜치로 초기화했습니다. 기준 커밋은 git log -1 --oneline으로 확인할 수 있고 생성 작업 기록·가상 환경·실행 로그는 소스와 분리해 관리합니다. 현재 확인 결과는 위 실행 기록이며 과거 문서의 일괄 성공 수치로 대체하지 않습니다.

실제 미디어와 시뮬레이션 구분

Late Night Mood의 실제 등록은 2026-10-03 기록입니다. WAV 1개와 JPEG 2개를 기존 원본에서 복사했고 당시 SHA-256과 메타데이터·SHACL 검증을 통과했습니다. 원본 생성 모델·프롬프트는 미확인입니다. 두 장면은 음원 전체를 나눈 배치 계획이며 최종 영상은 렌더링하지 않았습니다.

simulation.py와 run_pipeline.py는 작업 과정과 메타데이터를 실습합니다. 데모 결과는 계획·시뮬레이션으로 표시하고 외부 SPARQL 업데이트·webhook은 명시적으로 요청한 경우에만 전송합니다. 영상 생성 제출·다운로드·렌더링을 완료했다는 증거는 별도 미디어 실행기에서 확보해야 합니다.

출처 보고서는 RDF에 기록된 근거를 보여 주는 출력물입니다. 확인하지 못한 모델·원본 출처를 추정하지 않고 외부 인증이나 공식 보증 문서로 표현하지 않습니다.
